Why dsh-self

          
Pack once, freeze versions, reuse forever, share with anyone

          

            Split a crowded universal toolbox into dedicated appliances. A general-purpose agent host is great for exploration; once a workflow works well, freezing it into a standalone desktop installer makes daily reuse and team distribution effortless.
          

        


        

          

            PACK ONCE, REUSE
            
Pack once, reuse reliably

            
Each output is a real self-contained desktop application—not a thin web wrapper. Close Studio, work offline, or reopen months later: your workbench and local data keep running smoothly.

          

          

            FROZEN VERSIONS
            
Pinned dsh & plugins—immune to breaking upgrades

            
Electron, Node, the exact dsh host runtime, and every plugin version (plugins.*.lock.json) are sealed inside the package. Future upstream dsh or plugin updates will never break an already-built client; you only upgrade when you choose to rebuild.

          

          

            READY TO SHARE
            
Distribute directly to teammates or users

            
Send the .exe installer straight to others. Recipients need no Node, no dsh CLI, and no plugin setup—just double-click to install and land straight on the dedicated workbench.

          

        


        

          

            
Mixing plugins inside one shared dsh window

            
    
              
  • Bidding, design review, and legal files collide in one workspace and sidebar.
    • 
              
  • Sharing with others requires teaching them Node, dsh, plugin installation, and config tweaks.
    • 
              
  • Upstream dsh upgrades or plugin peer drift can break a working workflow overnight.
    • 
            

          


          

            
Packaging a dedicated client with dsh-self

            
    
              
  • Pack once with locked versions: Bundles fixed Electron, Node, dsh, and pinned plugins so upstream updates never break your workflow.
    • 
              
  • Direct redistribution: Hand the installer to others—double-click to open straight into the custom workbench with zero onboarding popups or telemetry.
    • 
              
  • Full OS isolation & controlled updates: Frozen productId, internalSlug, and userData allow side-by-side installs and intentional in-place upgrades whenever you rebuild.

dsh-self-studio Workbench

          
Six guided steps from a sentence to an installer

          

            Built strictly on official dsh@0.2.2-rc.5 public APIs (ctx.connection, ctx.slots, ctx.locale, ctx.layout) so it runs identically in dsh web and official Desktop.
          

        


        

          

            01
            
Requirements

            
Start from plain language, expand into an editable draft via your dsh default model (or offline fallback), attach reference images or an SSRF-guarded URL, or import an existing product.json.

          

          

            02
            
Blueprints

            
Compare Lite, Standard, and Pro options with live 1:1 light/dark window previews and minimal clarifying questions only when they change the workflow.

          

          

            03
            
Plugins

            
Runs 4-step static admission and 6-dimension conflict filtering, detects locally installed DSH plugins, supports per-action swaps, and suggests standard MCP alternatives when peer conflicts block a package.

          

          

            04
            
Appearance

            
Customize bilingual names, semver version, app icon (4 SVG presets or uploaded PNG/JPG/WebP), 8 light/dark color seeds (deriving 110+ --dsw-* tokens with WCAG 4.5:1 contrast clamping), layouts, and module order.

          

          

            05
            
Preview & Tweak

            
Launches an isolated child-process preview with dedicated session partition; theme and layout tweaks hot-refresh in under a second alongside conversational natural-language refinement and one-click rollback.

          

          

            06
            
Build & Release

            
Independent trust-root tools/builder validates snapshots and emits native Windows x64 NSIS .exe installers plus cross-platform recipes (portable bundle, GitHub Actions, Docker/remote) with SHA-256 receipts.

          

        

      

    


    

      

        

          
Engineering Depth

          
Isolation, upgrade safety, and defense in depth by default

          

            Every boundary is backed by unit and contract tests—external pages, uploaded files, and LLM outputs never bypass static schemas or package whitelists.
          

        


        

          

            IDENTITY & UPGRADE
            
Immutable identity vs. mutable brand

            
productId, internalSlug, nsisGuid, and appUserModelId are frozen at creation. Rename upgrades clean stale shortcuts, same-name siblings auto-disambiguate with (<shortId>), and NSIS customInit blocks schema downgrades.

          

          

            CaMeL + SSRF
            
Dual-channel taint split & SSRF guard

            
Visual/web extraction splits controlSafe enums from taintedDisplay text (never re-injected into planner prompts). An isolated fetch-worker blocks loopback, RFC1918, cloud metadata 169.254.169.254, CGNAT, NAT64, and non-80/443 ports.

          

          

            PREPACKAGED + FUSES
            
3-step prepackaged pipeline & dual-slot rollback

            
Read-only base-shell locks down Electron Fuses (RunAsNode: false, OnlyLoadAppFromAsar: true); pure-JS resedit stamps PE metadata before --prepackaged wraps the installer. Dual p-<seedHash> profile slots auto-rollback after 2 failed boots.

          

          

            OOXML & SHARP
            
Sandboxed DOCX & ultra-long PNG export

            
Bid adapter enforces 4-quota ZIP-bomb limits, strips w:altChunk/UNC paths, and previews inside an opaque-origin <iframe sandbox="allow-scripts"> with strict CSP. Design canvas normalizes EXIF orientation and tiles vector badges via sharp.composite past Cairo's 32,767 px limit.

          

        

      

    


    

      

        

          
Get dsh-self-studio

          
Install the official DSH plugin (v0.1.0 release-prepared)

          

            Declares engines.dsh: ">=0.2.2-rc.1 <0.3.0" and engines.node: ">=24.9", verified live on official dsh@0.2.2-rc.1 Desktop and 0.2.2-rc.5 via 10 automated release gates.
          

        


        

          

            

              
Option 1: Pack & install locally (Available now)

              Available
            

            
Run the 10-gate release packer in the dsh-self repo and install the generated .tgz into your official dsh profile:

            

              

                shell
                
              

              
node scripts/prepare-plugin-release.mjs --pack
dsh plugin --profile web add .dev/plugin-release/dsh-self-studio-0.1.0.tgz
dsh web

            

          


          

            

              
Option 2: npm & Custom Plugin Index (After public publish)

              Pending npm publish
            

            
Once published to npm, install by exact version or add our official DSH Custom Plugin Index under Settings → Plugins → Discover:

            

              

                shell / index url
                
              

              
# Exact npm install
dsh plugin --profile web add dsh-self-studio@0.1.0

# Official DSH Custom Plugin Index URL (format: 1)
https://dsh-self.octoooo.com/dsh/index.json

            

          

        


        

          Transparent disclosure: Locally built Windows NSIS installers are marked unsigned-local-test (no commercial signing certificate; internet distribution will trigger Windows SmartScreen). As a Host plugin, dsh-self-studio runs with the OS user's file and network permissions. See the Plugin Release Guide for the full checklist.
